# AI Story Generator — Frontend (Flutter) — Day 1

Covers the Day 1 plan: project setup plus OIDC login/logout with session
handling (FR-01, FR-02, FR-03), talking to the Django backend in `../backend`.

This folder ships only `pubspec.yaml` and `lib/` — Flutter's platform
folders (`android/`, `ios/`, `web/`, etc.) are generated by the Flutter SDK
on your machine, not hand-written, so merge them in first.

## 1. Setup

```bash
cd frontend
flutter create --project-name ai_story_generator --org com.example .
# This scaffolds android/, ios/, web/, etc. WITHOUT overwriting the
# pubspec.yaml and lib/ that are already in this folder — confirm "no" if
# it asks to overwrite pubspec.yaml, then re-check `git diff` to be safe.
flutter pub get
```

## 2. Point the app at your backend

Backend base URL is read from a compile-time define (see
`lib/core/config/app_config.dart`), default `http://localhost:8000`.

```bash
# Android emulator (10.0.2.2 maps to the host machine's localhost):
flutter run --dart-define=BACKEND_BASE_URL=http://10.0.2.2:8000

# iOS simulator / desktop / web (backend on the same machine):
flutter run --dart-define=BACKEND_BASE_URL=http://localhost:8000
```

## 3. Platform config needed for local HTTP during dev

Since the backend runs on plain HTTP in local dev, allow cleartext traffic:

- **Android**: in `android/app/src/main/AndroidManifest.xml`, add
  `android:usesCleartextTraffic="true"` to the `<application>` tag (dev only
  — switch to HTTPS and remove this before shipping).
- **iOS**: in `ios/Runner/Info.plist`, add an `NSAppTransportSecurity` /
  `NSAllowsArbitraryLoads` exception for local dev (same caveat).

## 4. How login works (Day 1)

1. `LoginScreen` opens an embedded web view at
   `{backend}/accounts/google/login/`.
2. The user completes Google's OIDC consent screen; Django's session cookie
   is set and the browser is redirected to `{backend}/api/auth/me/`.
3. The web view detects that redirect, reads the session cookie via
   `CookieManager`, and hands it to `AuthService`, which stores it in a
   `PersistCookieJar` so it survives app restarts.
4. `AuthState.completeLogin()` re-checks `/api/auth/me/` (now authenticated)
   and the app shows `HomeScreen`.
5. Logging out calls `/accounts/logout/` then clears the local cookie jar.

## 5. Project layout

```
frontend/
  lib/
    core/config/app_config.dart   # single source of truth for backend URLs
    features/
      auth/
        auth_service.dart         # cookie-aware HTTP client + session calls
        auth_state.dart           # ChangeNotifier: unknown/authenticated/unauthenticated
        login_screen.dart         # embedded OIDC web view
      home/
        home_screen.dart          # placeholder shell post-login
    main.dart                     # bootstraps AuthState, routes login vs home
```

## 6. What's deliberately NOT in Day 1

Create-story form, My Stories list/detail, edit/delete, error-handling UX,
dark-mode toggle, and search/sort screens are Day 2–6 scope and not
implemented yet.
